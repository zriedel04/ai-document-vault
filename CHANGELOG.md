# Changelog

All notable changes are recorded here, following [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Public reference texts for the OCR and PDF spikes in `demo/corpus/references/`, generated by `demo/generate/references.py` from the same content the renderer draws: one `NAME.txt` per screenshot and receipt (the drawn text in reading order) and a `NAME.txt` and `NAME.headings.txt` per text PDF, at each file's own path. They are not documents (the manifest does not list them and no eval question cites them), and tests check them against the drawn pictures and the PDFs' own bytes, so `ocr` and `pdf` can now be run on public data with `--references`.
- **Move to trash** and **Restore** on a document's page in the app: one button for the document's current place, which shows the state the backend returns and a short confirmation, is disabled while its request runs, shows a fixed error text when the backend refuses (4xx), loads the document again and shows it as it is when the outcome is unknown (a 5xx, a lost connection or an answer that does not prove the move), and brings the token notice back on a 401.
- Worker pool (`vault.jobs.worker`, ADR 0005): threads in the server process that claim jobs per stage up to a configurable limit (`[workers]`), complete them or record the failed attempt by class name, sleep until woken instead of polling, pause and resume, and stop on shutdown. A claim still in progress when the pool is paused or stopped gives its job back unstarted (`JobQueue.release`, which also returns the attempt), and `pause()` waits for it. Started with the server after recovery; no stage has a handler yet.
- Start-up sweep for blobs that no database row uses (`vault.ingest.orphans`, `BlobStore.set_aside`): each is moved, unchanged and read-only, to `blobs/orphans/` instead of being deleted; links and doubled names are only counted, a failed move does not stop start-up, and only counts are logged.
- Pages table (`pages`, migration `0004`) and repository (`vault.db.pages`): the extracted text of each page of a document version with its headings, extractor version and encoding, replaced as a whole in one transaction and checked on the way in and out (contiguous page numbers, headings inside their page and in order, a canonical codec name). Not written by anything yet.
- Documents section in the app: a library page (`/documents`) with Library and Trash tabs, sorting by date added, name or size, paging, and the view kept in the address; a page for each document with its hash, version, imports and processing steps; and **Download original**, which fetches the file with the token and saves it under the document's name.
- Trash and restore: `POST /api/documents/{id}/trash` and `POST /api/documents/{id}/restore` move a document to the trash and back, keeping its state, file, versions, imports and jobs; both are idempotent and return the document as it now is.
- Download of a document's original `GET /api/documents/{id}/file`: the current bytes as an attachment, under the first import's name, with the validator's media type.
- Document details `GET /api/documents/{id}`: hash, current version, every import source and the processing jobs, read from one snapshot (`vault.db.engine.read_snapshot`).
- Document list `GET /api/documents`: one page of the documents in use or in the trash, sorted on the server by time added, name or size, with the name of the first import, the size and type of the current version, and the total.
- Upload endpoint `POST /api/imports/upload`: one file as the request body, its name, batch and modification time in headers (never in the address), streamed to a staging file under the size limit and handed to the importer.
- Project licence: Apache-2.0 (`LICENSE`, ADR 0017), declared in the backend, frontend and demo generator package metadata; the backend's wheel and sdist include the licence text.
- Import of one file (`vault.ingest.importer`): validate, store the blob, validate the stored copy, then record a new document with its version, source and `extract` job, or a new source for the document that already holds the same bytes. Concurrent imports of the same bytes make one document.
- Persistent job queue (`vault.jobs.queue`, `jobs` table, migration `0003`, ADR 0005): enqueue without duplicates, an atomic claim, back-off and a failed state after the last attempt, retry, and recovery at start-up of jobs a killed process left running. Error messages are never stored, only the exception's class name.
- Document tables (`blobs`, `documents`, `document_versions`, `import_sources`, migration `0002`) with ULID ids (`vault.db.ids`) and CHECK constraints on every value the application writes, a current version that must belong to its document, and the `trashed` state of ADR 0005 with the state to restore; the first part of Phase 1. Nothing writes them yet.
- Launcher `vault.ps1` (`install`, `run`, `stop`, `dev`) for Windows PowerShell 5.1 and PowerShell 7: it builds the app, starts the server in the background, waits for it, opens the browser with the token in the address fragment (ADR 0016) and stops it again, with PowerShell tests and a `Launcher (Windows)` CI job that runs the commands against a real server. It refuses a port that something else holds, makes commands started together take turns, keeps a vault folder with non-ASCII letters intact in its record, opens the browser only once the process it started answers with its own random launch id (`/api/health` and Vite's `/__vault/launch`), and never removes the record of a server it did not end (`docs/launcher.md`).
- Security headers on every response (`vault.core.headers`): a Content-Security-Policy that allows scripts only from this origin as files and sends requests, images and fonts nowhere else, plus `nosniff`, `no-referrer`, no framing and same-origin opener and resource policies, as ADR 0016 recommends before pages show document text. Checked in Chromium against the built app with no policy violations.
- Phase 0 spike scripts in `scripts/spikes/` (sqlite-vec, embedding model, OCR engine, PDF extraction) that record metrics only, with unit tests that use fakes and a CI job. Nothing has been measured yet; the spikes run on the Windows PC.
- Seven "find the document" questions in the public eval set (`find_document: true`, reworded from existing lookups in `demo/generate/questions.py`), so the embedding spike can report document-level Hit@1 on the public data.
- Access token in the page (`frontend/src/api/token.ts`, ADR 0016): the page takes the token from the address fragment `#token=...`, removes it from the address bar, keeps it in `sessionStorage` and sends it as a bearer header; without one it shows a notice with a password field and makes no request that would be refused. The API client, a session check on the dashboard and tests for each are included.
- Content-addressed blob store (`vault.storage.blobs`): hashing copy into `sha256/aa/bb/<hash>.<ext>`, read-only blobs, exact-duplicate handling that is safe under concurrent imports even under different extensions (a claim on the hash), an integrity error when a non-blob (a folder, a symbolic link or a junction) occupies a blob's place or one of its folders, a scan that reports every odd entry, start-up recovery (`clean_temp()` then `seal()`), `seal()` to restore read-only blobs after a crash, atomic publication with temporary-file cleanup, a size limit, `verify`, `scan` and `delete`.
- File validation (`vault.ingest.validate`): type by content, extension allowlist, size cap, and DOCX archive limits (checked before the zip directory is opened), and byte-order-marked text decoded and judged like any other, so spoofed, oversized and hostile files are refused before parsing.
- Local security and database foundation: Host, Origin and token checks on every request, a `current_user` seam, vault folder rules (never inside a Git repository), SQLite in WAL mode through SQLAlchemy Core, and an Alembic baseline migration.
- Frontend shell in `frontend/`: Vite, React, TypeScript and Mantine with Dashboard, Documents, Search, Ask and Settings placeholders, a light/dark toggle, a typed API client generated from the backend's OpenAPI schema and a backend health badge. The backend serves the built frontend from the same origin. ESLint, Prettier, `tsc`, Vitest, an npm licence check and `npm audit` run in CI.
- Synthetic demo corpus in `demo/corpus/` (44 fictional documents: text and scanned PDFs, DOCX in two versions, TXT, Markdown, CSV, PNG, JPG, duplicates), its reproducible generator in `demo/generate/`, a 60-question public eval set in `eval/public/questions.yaml` with a validation test, and `config.demo.toml`.
- Backend skeleton in `backend/`: FastAPI app factory with `GET /api/health`, TOML settings with environment overrides, logging that never records document content, pytest, Ruff, mypy, a Python licence check and `pip-audit` in CI.
- Repository foundation: ignore rules, repository safety check, pre-commit hooks, CI, templates and contributor docs.
- Architecture plan (revision 2) in `docs/architecture.md`, a template and 16 ADRs (13 Accepted, 3 Proposed pending Windows spikes), and an ADR structure check.

### Changed

- The OCR and PDF spikes read the `--images` or `--pdfs` folder and its subfolders, and find a reference file next to its image or PDF or in `--references` at the same relative path, so one run measures the whole public corpus (three courses each have a `syllabus.pdf`). A link anywhere in the tree or on the way to a reference file below `--references` (a symbolic link, a Windows junction or another reparse point) or a subfolder that cannot be listed stops the run, instead of being followed or skipped unseen.
- `@types/node` is pinned to the oldest Node.js release the frontend supports (22.13, was 22.20), and Dependabot no longer proposes its major or minor updates; a test in `scripts/tests/test_node_types.py` checks that `engines.node`, CI and the types agree.
- Dependabot no longer proposes a TypeScript major version (TypeScript 7 does not install next to `openapi-typescript` and `typescript-eslint`, so the npm group failed to resolve) or a `uv-build` bump (the build backend is pinned to the tested minor series and is bumped by hand).
