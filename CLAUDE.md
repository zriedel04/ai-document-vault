# Claude Code specifics

The shared project rules, workflow, review process and commands are in `AGENTS.md`, imported above. This file adds only what is specific to Claude Code.

## Responding to review

Codex may review any PR and post comments. Retrieve every finding and sort each into one of four categories before touching code:

| Category | What to do |
| --- | --- |
| Valid, fix now | Make the smallest appropriate fix, add or update tests, run the relevant checks, push, reply on the thread with the commit and what changed, and resolve it |
| Valid, but the proposed fix should change | Fix the underlying problem a better way and say in the reply why the suggestion was not applied as written |
| Valid, but outside this PR's scope | Do not widen the PR. Reply with why, and recommend a follow-up issue (open it only if the owner agrees) |
| Not valid | Reply with the evidence, such as the `file:line` or a test that shows it, and resolve the thread |

- Never apply a suggestion blindly, and never dismiss one without checking it.
- Address one Codex pass at a time. Do not request another review and do not loop: after fixing a pass, report to the owner, who decides whether another review is needed.
- Do not merge a pull request, whatever its review or CI state. The owner merges after explicitly approving.
- Treat repeated findings as a signal about the author, not just the code. Record the pattern under "Lessons from review" below so the next change avoids it.

## Lessons from review

These patterns came up repeatedly in Codex's reviews of the repository safety check (`scripts/check_repo_safety.py`, six review rounds, about fifteen findings) and of the ADR checker. Check for them before pushing, not after a review.

1. **Fix the class, not the instance.** A finding names one example (`.epub`, `.ppk`, a zip). Before replying, list the whole class (every ebook format, every key format, every archive format) and cover all of it, with a test that fails when a member is missing. Fixing only the named example invited the next round. The same holds for a permission: the blob seal tested one write bit (the owner's), so a mode such as `0o446` stayed writable by anyone; compare the whole mode with the exact value you want (`0o444`) instead of testing the bit a finding names. The blob store showed it twice: uniqueness was enforced on the file name (`<hash>.txt`) instead of on the hash it stands for, so the same bytes imported as `.txt` and `.md` made two blobs, and a guarantee about the end state (every blob is read-only) held only if the process was not killed in between. Enforce a rule on the key, not on a name derived from it (and treat two names for one key as damage that a lookup reports, a scan does not trust and a delete removes completely, instead of letting `find` pick the first), and for every step that has a crash window ask what the next start-up does about it (`seal()`, `clean_temp()`).
2. **Close every layer of a rule.** A protection usually exists in several places that must agree: `.gitignore`, the path rule in the checker, the content rule (file signature), the staged index, the working tree and git history. Adding a suffix without its signature check, or an ignore rule without a checker rule (`vault/`, `*.bak`), left a gap. When adding to one layer, list the others and cover them or say why not. The start-up access check listed the vault's files by name and missed SQLite's rollback journal, which the safety check and `.gitignore` already knew as private database data: when a rule names a file kind in one place, search the repository for the same kind elsewhere, and check a folder by listing it rather than by a list of names. The next round found the same gap one level down: the check covered the folder and its direct entries but not the files below the subfolders, and Windows lets any account open a file by its path when its own list names it, so a rule about access to files must cover the whole tree, not a fixed depth.
3. **Assume the bypass.** Safety guards must survive `git add -f`, a renamed or deleted file, a file edited after staging, a file with the wrong extension, and a blob that only exists in history. Test each of these as a scenario, not just the happy path. A rule that holds when data is built can be bypassed when it is read back: the spike report refused free text when a script made it, but `merge` accepted any title or method from a JSON file. Apply the same checks at every entry, loading included. That includes the range of a value: a name allowlist still let `recall_at_10: -5` and `load_seconds: true` through, so each metric has a kind (count, ratio, amount, flag) that a loaded value must fit. Mutating a checked structure after it was built is a bypass too: the OCR spike wrote the whole Tesseract version line into an already validated `Environment`, so the report was written but `merge` rejected it on read-back. Rebuild it through the constructor (`with_package`) and test the write, read and merge round trip, not only the write. A report must also say what it measured (a `public_dataset` flag, counted occurrences), not leave the reader to assume it. For code that touches the file system, the bypass is a link: `is_file()`, `stat()`, `chmod()` and `mkdir(exist_ok=True)` all follow symbolic links, so a link in the place of a blob or one of its folders made the blob store find, chmod or publish into something outside the vault. Use `lstat`, refuse links and Windows reparse points (junctions have the reparse attribute, not the symlink mode) at every level before using a path, report them in the integrity scan, and test a link to an outside file, a link at each folder level and a dangling link. Also test the failure path of an operation that first loosens something (a delete that made a blob writable and then failed left it writable). Links are a class with more members than symlinks and junctions: a hard link is a regular file with the same inode (check the link count before `chmod`), and every folder the code works in (the temporary folder, not only the hash folders) needs the same check. A recovery method that nothing calls is not a recovery: wire it into start-up and test the start-up.
4. **Read the whole input.** Fixed-size reads (16 bytes) missed signatures that sit deeper in the file (tar at offset 257). State the assumption about input size or position and test the boundary. The same goes for the end of a string: in Python `$` also matches before a trailing newline, so `re.match(r"^...$", "name\n")` succeeds. Check a whole value with `fullmatch` and test every pattern with a trailing `\n`, `\r` and space. Two more forms from the file validator: a check that runs after a library has built its objects is too late (`zipfile` reads the whole central directory before any entry count can be checked, so bound the claim from the end record first and prove with a test that the library is never opened), and a marker says how to read the content, not that the content is valid (a byte order mark made any bytes after it text; decode them and judge the result). Two more from the second pass: when you copy a library's parsing to judge a claim first, copy its whole rule, not the common layout (`zipfile` follows the ZIP64 locator to a record that may sit before an extensible data sector, so a fixed-offset read judged a different record than the library would use; build the unusual layout as a file, prove with a control that the library opens it, remembering that this differs between patch releases of Python and CI runs two of them, and mutate the code back to see the test fail), and the end of the input is a different case from a cut input (a head cut mid-character is fine, a whole file that ends mid-character is not, so pass that fact to the decoder). The third pass showed the other half: the project supports every 3.12 patch release, and `zipfile` differs between them, so a preflight that mirrors one release judges a different record than another release reads. When code must agree with a library, bound every place any supported version may read (and test that the value the installed version reads is among those judged, on each Python in CI), or raise the minimum version. The same test found a field-index slip (`fields[8]` is the directory size, not the entry count) that earlier fixtures hid because their numbers were all huge: write a fixture with distinct small values for each field. Text the owner writes by hand on Windows is input too, and it is not always UTF-8 without a mark: Windows PowerShell 5.1 writes UTF-16 with `>` and a byte order mark with `Set-Content -Encoding UTF8`, and a mark read as a character stuck to the first heading of a reference file and lowered the score without a warning. Decode such files by their mark (`corpus.decode_text`), test each encoding a Windows tool writes (UTF-32 too), and refuse what no mark explains: UTF-16 without one is valid UTF-8 with a NUL between the letters.
5. **Review your own diff adversarially before pushing.** Ask what a careless or hostile user would commit that this change still lets through, and what legitimate file it would wrongly block (the planned `backend/src/vault/` package is source code, not a vault folder). When a flag changes what an output means (`public_dataset` false), search every fixed text that describes that output for the old meaning: the metric was fixed and the Method sentence still said "public question" in every private report. Compare every new dependency and framework with the stack table in `docs/architecture.md`: the frontend shell shipped React Router where the approved plan says TanStack Router, which needed either a switch or an ADR. For a score, ask what partial answer it would still credit: accepting either half of a long quote gave full recall to a chunk that held only the generic half of a sentence. Credit only the whole, make the data fit the rule (the chunk overlap follows the longest quote) and report what cannot fit. The same goes for a measurement: compute each metric as the plan defines it (Hit@1 is by document and only for find-the-document questions, not a passage match averaged over every question), let one unreadable input be skipped and counted instead of stopping the whole run, and when results are merged keep what each row was measured in (the CPU and CUDA runs of the embedding spike have different environments). A benchmark must also see what the product would see: the embedding spike chunked exact duplicates that the import pipeline never indexes, so identical copies took several of the ten ranked places and could push a required passage out; embed only the original and let a citation of the copy count as the original. Two scoring rules must also agree on one definition: the score gave an alternative full credit while the filter that picks the questions to score ignored alternatives, so a scan with a readable alternative was dropped; write the rule once (`can_be_scored`) and use it in both places. And a value found after an expensive run (the GPU name) must be sanitised like one found before it: a refusal at the end throws the measurement away, so fall back to `unknown`. The same holds for the place the result goes: the name check for the report found a clash before the run, but a folder that could not be created or written was found only when the report was written, so make and try every destination before the expensive step, not just check that its names are free. The same flag was missing from two of the four spikes: `public_dataset` and a dataset-specific file name were added to the embedding report after the first review, and the OCR and PDF reports, which ADRs 0014 and 0015 also need on public and private data, kept one name and no flag until the next pass found it. When a fix adds a field to one output, list every sibling output of the same family and add it to each in the same change.
6. **Do not state a claim you have not checked.** One reply said every archive suffix had a signature check when `.tar` and `.iso` did not. Verify a claim against the code before posting it.
7. **Validate what a value points at, not just its shape.** A status naming a superseding ADR, a link to spike results and a file name pattern each passed a loose check (a regex, `is_file()`, a glob) while accepting nonsense (`ADR 9999`, `docs/architecture.md`, `0016_typo.md`). For every reference or naming rule, test a missing target, a wrong kind of target, and a name that nearly matches, and make the checker report what it skips instead of ignoring it. Check the target's state and contents too (a replacement ADR must be Accepted and point back; a spike file must have its sections filled in), and check both directions of a link. Even so, a structural check cannot prove a fact such as "the experiment was run on the Windows PC": say so in the docs and leave that to the owner's review. The spike report loader repeated this for names: it fixed the title, question and method, but candidate and metric names were only checked by shape (`^[a-z0-9_-]+$`), so a lower-case word from a document passed as a metric name. When a value can come from a file, list the values the code can produce and check against that list, per spike, and add a test that ties each list to the code that emits it (adapter names, emitted metrics). The same gap was left in the values after the names were fixed: package versions were checked as "letters, digits and dots", which accepts `patient-diagnosis-confidential`. A value from a file is a number or a fixed sentinel; a word of the right shape is free text, so check the grammar of the value (a version is numbers with a closed set of suffixes, plus `not installed` and `unknown`) and make the code that reads the machine fall back to the sentinel instead of failing. The machine description (CPU, GPU, system) was the last field left on a loose pattern, "letters, digits and a few marks", which accepts `Patient diagnosis confidential`; a free-form field has to become a closed vocabulary (hardware words plus model numbers) with `unknown` for anything else, because "the owner reads it" is a review step and not a check. The same gap was left in the rows after the names and values were fixed: the merge checked that a row's metrics were a subset of the spike's vocabulary, so an empty row, a row without `public_dataset` or `documents_skipped`, and a row with another candidate's figures (video memory on a CPU run, a peak for Tesseract, heading scores for the extractor that finds no headings) all passed. A report row has a shape per candidate (`RowShape`: the metrics every row has, the ones a run may lack, and the groups that come whole or not at all, plus a `consistent` rule for what the numbers of a row say about each other: Hit@1 exists exactly when its question count is above 0, scores exactly when questions were scored, outcomes add up), so check what a row must contain and not only what it may contain, derive the candidate names from the same table, and add a test that every row the spikes really write fits its shape and that no shape goes unused. A reference such as `exact_duplicate_of` is a claim about the file as well as a name: the loader refuses a target that is not listed, itself or a loop, and the corpus builder compares the bytes, because dropping a document on the strength of a mark scores the questions against the wrong corpus. Fixing the groups left that second half open and the next review found it: check the relations between fields as well as their presence, and run the rule over every row the spikes really write. The eval paths are references too: a source path the manifest does not list made the question unscorable, and it was dropped from Recall and MRR as if its scan were unreadable; check each cited path against the manifest before the run, spelled as scoring compares it (exactly, not as Windows would), and give the question's position in the file, never its id or the path (both are the owner's free text, and a question id such as a client's name reached the console in one review). A figure that is computed from another needs that other figure in the row, and a group's own count has to be positive (a heading score with no `files_with_heading_reference` claimed accuracy against no labelled PDFs): for every derived figure ask which figure it is computed from and what the script writes when that figure is absent, and check the formula where one exists (F1 from recall and precision) with the rounding the report applies. Bounds belong with the relations: `references_used <= files_ok` was missed because the rule only asked whether the count was above 0, so for every derived count ask which count it is a part of. A requirement can belong to one candidate and not the whole spike (the Tesseract version, which is a program and not a package): put it on the row shape and apply it to the environment that applies to the row. A requirement that a package be there is a requirement that it be installed: the sentinel `not installed` passed a check that only looked for the key, so for every candidate list the packages it runs on in its row shape, refuse the sentinel for those and allow it for the others. A blank string passes a type check, so check the content of every text field a score depends on (a blank question is an empty query). The same goes for the promise that one unreadable input is skipped and counted: it has to cover every operating-system failure at every step that touches the file (the size check, the read, the byte comparison of a duplicate), not the one the format's own library reports, because a file another Windows program holds fails with `OSError` after `safe_file` has accepted it. The formula rule was applied to the one figure a review named (F1) and the next pass found another (the projected hours, `vault_chunks_assumed / chunks_per_second / 3600`): list every figure each script computes from others in its row, in every spike at once (the projection, the failures-as-errors mean, a share of a count such as Hit@1, a precision beside its false positives, a median beside its percentile), and check each with one rounding rule (`rounded_within`, `whole_share` and `right_share` in `report.py`) instead of a tolerance picked per check.
8. **Allow by construction, not by appearance.** A privacy guarantee that rests on a value "looking harmless" fails on the first harmless-looking leak: the logging check let a one-word piece of document text through because it matched the identifier pattern, and it copied field names into the log unchecked. Make the default deny (a type or an explicit marker says a value is safe), cover every channel into the output (values, field names, event names, logger names, exception messages, third-party libraries, whose loggers such as uvicorn's access log write request URLs, and the formatter's own failure path, because Python prints the raw message when a handler raises), and an uncaught exception at the command line (`FileNotFoundError` and a library's `ValueError` quote the private folder or file they were reading, in the message and in the traceback): print a message in full only for an error class this package owns, and only the class name for everything else, and test with realistic document text, not only obviously bad input. A type is not provenance: after redacting `str` the next round found that a plain `int` or `float` parsed from a document leaked too, so a value needs an explicit marker (`metric()`, `identifier()`) that says the application produced it. When a parser skips a clause it does not understand (an SPDX `WITH` exception), it must fail closed. When two checks read the same data, make them read the same source through one function: the licence gate decided by the SPDX expression while the reviewed-exception check looked at any field, so an old MPL classifier rescued a GPL expression. The same rule applies to access control: the Windows folder check listed broad groups to reject (Everyone, Users) and so let a second named account or a domain group through; it now accepts only the current user and a few system principals. A credential's transport has a scope too: the install token in a `SameSite=Strict` cookie reached every port on `localhost`, because cookies are scoped by host and not by port; it is now sent only as an `Authorization` header from the page's own origin storage. When a secret leaves the process, ask who else receives it, not only who may send it. The spike report showed the same shape in scoring: the scorer accepted an alternative passage, but the count of passages no chunk holds looked only at the required one, so a mistyped alternative lowered every score unreported, and a counter the corpus builder filled (`skipped`) had no reader at all. A figure that says how far to trust a score must use the same rule as the score (one function for "acceptable passage"), and a value that is computed must reach the report or be removed. The success message is an output channel too: the spike CLI printed the `--out` folder the caller typed (`D:\Clients\Patient-Name`) after its error output had been cleaned, so print only names this package built itself and test a run with a private-looking folder. The same pass found it once more in my own new check: an error that "names the question's id" printed a free-text id, because an id is as private as the path; before writing a message that names anything from an input file, ask where that name came from, and use a number the code counted. Fields typed by hand need the same care in their kind (`bool("false")` is `True`): read a manifest or eval field as exactly its kind, refuse the rest, and default only an absent one. The command-line parser is an output channel as well: `argparse` prints the rejected token before any of this package's error handling runs, so a private folder typed in the wrong place reached the console; subclass the parser so that its errors are fixed text, and test a malformed command line made of private-looking names for each way of failing (an extra word, a bad value, an unknown option, a missing value, an abbreviation). The libraries' channel was missed again in the spike command line although this lesson names it: pdfminer, under pdfplumber, logs the tokens of a malformed page, the words on it among them, through Python's last-resort handler, and RapidOCR gives its logger a console handler of its own. Run a real library on a synthetic malformed file and look at the console before claiming that nothing private is printed; a command line that runs libraries on private files switches their log records and warnings off for the command (`libraries_silenced`), and a test drives each way a library writes.
9. **Check what your tooling enforces before claiming it.** The logging docstring said mypy rejects a computed event name (it does not enforce `LiteralString`) and that libraries "never see document content" (uvicorn logs every request URL). Run the claim as an experiment (a short file that should fail, a request through a real server) before writing it down, and make a regression test fail when you remove the fix. A command in the docs is a claim too, about the shell it names: `merge spike-results\embedding-*.json` was documented for Windows PowerShell, which passes the star to Python as text, so either expand the pattern in the program or give a form every shell runs, and test the pattern as the program receives it. The same applies to a label: the OCR candidate was reported as PP-OCRv5 while the library's default model was PP-OCRv4 (and PP-OCRv6 from release 3.9), which would have published another model's accuracy under that name. Read the library's own default config (download the release and look), set what the label names explicitly, and test that the configuration passes it. A measurement has the same trap: the host's working set is not video memory, so a CUDA run needs the GPU's own peak (allocated and reserved) next to it, and each metric's docstring says what it does not include. A figure can also belong to another process: the Tesseract candidate runs as a child program, so the spike's own peak working set was the wrapper's, set beside RapidOCR's real number; leave a figure out when it does not measure the candidate, and say how to get it. A high-water mark is also a property of the order of the runs in one process: the sqlite-vec rows read `peak_memory_mib` after each size, so `--sizes 100000 10000` reported the large store's peak in the small row; refuse an order that makes a figure mean something else (ascending, each once) or measure each in its own process. Record every setting that changes a measurement in the row (the embedding batch size), and check that the setting reaches the code that does the work, not only the report (the batch size was recorded but the encoder kept its own default of 32, so a run asked for 64 was reported as 64 and measured at 32), and say in the report when the benchmark's input is not the product's (the spike's 800-character windows are not the planned structure-aware chunks). A name that points at something that moves does not identify it: a model repository's default branch moves between the public and the private run, so the report records the commit that was loaded (found after the run and stored as `unknown` if it cannot be read), and a pin that cannot be checked is not invented. The same goes for a race fix: the blob store claim passed the Windows job once and failed on the next run, because Windows reports a name that is being deleted as `PermissionError`, not `FileExistsError`. One green run proves nothing about a race, so loop the race test many times, and say in the reply what was run on which system. A correctness check must compare what the product consumes: the sqlite-vec check compared the sets of the ten ids, so the right ten from farthest to nearest scored as a perfect match, though the application uses the ranking; compare the ordered list, and write the tolerance for ties (float32 against float64) as a rule with a test for each wrong case (reversed, repeated, missing, outside the data). A failure of the setup is not a result: the PDF spike counted every file as failed when its library was missing, because the handler that counts per-file failures also caught the missing-library error, the sqlite-vec probe reported "does not load" when the package was not installed, and the embedding corpus skipped every PDF as unreadable without its reader. Load the libraries once, before the loop and outside the handler that counts failures, and outside the timed section too (the first file's time had held the import of pdfplumber, and RapidOCR's first load downloads its models). A command is a claim about the tool as well as the shell: `uv sync --extra X` makes the environment hold exactly X, so a hint to install one extra removed the libraries of the other spikes.
10. **Check that interchangeable evidence is complete.** An eval `alternative` counts as a full answer, so a passage that gives only part of it (a date without the time, one of three reasons) inflates retrieval scores. The first review found one, and the audit found three more. For every alternative, compare it with the whole expected answer; `test_corpus.py` checks that the sources and each alternative carry every number of the expected answer and that no one document holds all the quotes of a `multi_doc` question, and the facts in words are yours to check. The second review round found the same gap again in the sources (three requirements missing from a list) and a `multi_doc` question one document could answer. The fourth round found the other direction: a `multi_doc` source that was not needed because another cited document repeated its fact (the email restated the syllabus rule, and the journal and the email both dated the breakage), and a version question whose baseline was only a distractor. For every `multi_doc` question, remove each source in turn and ask whether the rest still answer it; a mechanical number check was tried and only flagged incidental matches, so this stays a review step. The fifth round found the opposite gap: a document that also answers the question was not accepted (the edited standup kept the SQLite line; the project journal restated the chat decision), so a correct retrieval would score as a miss. `test_corpus.py` now fails if any other document holds a source quote verbatim; a paraphrase in another document is again a review step. For every answerable question, ask which other documents give the whole answer, and leave out one that gives only part of it (the journal has the laptop repair but not that Sam held the draft). The sixth round found the group form of the same gap: two syllabi that each give one final date answered the "which final comes first" question together, and the eval format only has single-passage alternatives, so that question was replaced. If a fact is spread over documents in a way an alternative cannot express, change the question and do not ship the gap. The seventh round found the sources side again, in two forms: an answer that names a shop the sources do not mention, and an answer that says what is absent ("not yet graded") while citing only one row of the table, which cannot show an absence. `test_corpus.py` now checks that every name in an answer is in a source quote and that the absence question cites the whole table. For a claim that something is missing, cite the complete list. The eighth round found the same two gaps in other questions: a passage taken out of its context cannot support the answer (a CSV row without its header row does not say whose hours `41` are, and a total does not show what it adds up), a comparison between two versions needs both ends of both lists (the last item and the next heading) to show that nothing else was added, and a history question left out a stage of the decision (the requirement that put chat in for a while) because that document was listed as a distractor. For every cited passage, ask whether it still proves the claim when read alone, and for every distractor, ask whether it is a stage of the story. `test_corpus.py` now requires CSV sources to be the whole table, the version comparison to cite the list ends, and the chat question to cite the first requirements draft. The ninth round found the absence question again: it now cited the whole grades table but only two items of the syllabus list that names every component, so the list that shows what the course has in all was still not whole. The class is "a claim about what is missing needs the whole of both sides", so the question now cites the complete grading list too, and `test_corpus.py` compares it with the syllabus text. The tenth pass found the question side of the same gap: when a question was reworded into "which document ..." form, its answer and sources still carried facts it no longer asked for (the five-point penalty, the time split), so a system that named the right document and left them out would be scored down. After rewording a question, compare its text with every fact in the answer and every cited passage, and ask for the fact or drop it. A topic is not a request: "which document gives the penalty" mentions the penalty but only asks for the document, so the second pass found five more questions I had called complete. Write the question as "which document, and what ..." for each fact the answer holds, and check each one against the answer line by line instead of by impression. The eleventh pass found the scoring side of the alternative: Recall ignored an alternative for a question with several sources while MRR counted it, so one retrieval was a complete miss and a rank-one hit; define one function for the passages that count (`accepted_passages`) and use it in every score, and refuse the input shape that the format cannot express (an alternative stands for one passage, so only a question with one source has them).

Add to this list when a new pattern appears in review, and remove entries that no longer apply.

## Keeping documents current

- Update `AGENTS.md`, this file, ADRs, tests and architecture docs in the same PR as the change they describe.
- A rule that applies to every AI tool belongs in `AGENTS.md`. Put it here only if it is meaningful to Claude Code alone.
